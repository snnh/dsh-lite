# Agent Note: Model defaults come from the model's family

Status: implemented

[English](2026-10-10-service-lite-model-family-defaults.md) | 中文

## Problem

手写的模型条目必须把没声明的东西全部重述一遍，而 `dsh-llm-service-lite` 对其余部分的答案是它手上最保守的那一个（2026-10-10）。

部署里写下 `models: [{ id: deepseek-v4-flash }]`，得到的是一个纯文本、没有思考开关、没有档位阶梯的模型——尽管厂商自己的文档写明这个 id 接受图片、开关写法是 `thinking: { type }`、提供 `low`/`high`/`max`、并在调用方未指定时使用 `high`。更糟的是其中三条事实并不是用户能猜到的偏好：既有思考是否必须回传（DeepSeek V4 与 MiMo 在缺失时用 400 拒绝后续轮次，Kimi K3 与 K2.7 始终保留，glm-5.3 根本无法关闭思考）、厂商默认用哪一档、以及哪些模型接受图片。用户只能逐个翻八家厂商的平台文档，再手工誊写答案。

Anthropic 传输还有一个相关缺口：该协议要求每个请求都带 `max_tokens`，于是适配器用模型自己的 `maxTokens` 填充——那是能力，不是「这次请求该要多少」的决定。结果是路由声明的容量静默成为每个请求的输出上限，而没人声明容量的模型则拿到路由级兜底值。

## Decision

**一张经过核对的家族表填补档案留空的部分。** `src/model-defaults.ts` 每个家族一条规则——匹配模式，加上该家族自家平台有据可查的事实：接受的模态、`thinkingStyle`、档位阶梯、厂商默认档、思考是否返回以及是否回传、以及 Anthropic 输出上限。规则按顺序对**小写化**的模型 id 自上而下匹配，因此具体规则必须排在本家族的通用规则之前。

**每条条目受四条规则约束，文件把这四条写成自己的契约。** 档案永远优先：表只填补空缺、绝不覆盖，已有路由原样保留自己声明的字段。不发明事实：每条条目记下它的出处文档，线上拼写未获确认的家族宁可不写。只认模型自家部署：中转商、网关或聚合站对同一模型 id 的要求从不作为出处——这正是别家目录里托管的 DeepSeek、GLM、Kimi、MiniMax 被读过却从未被引用的原因。永不默认采样参数：`temperature`、`top_p`、`top_k` 一律留空，因为各家在思考模式下的可用范围并不一致，端点自己的默认胜过臆造的数值。

**思维链回传是一条带强制底线的声明。** `capabilities.replayReasoning` 决定既有思考是否发回。缺省交给模型家族；`true` 在家族不主动回传时打开；对于后续轮次缺它就被拒绝的家族，`false` 会被按名拒绝——这与「传输层履行不了的声明」同等待遇，因为会回 400 的端点不是偏好问题。只写了 `reasoningContent: true` 的档案继续回传，这也是该开关出现之前写下的档案本就依赖的读法。

**默认档位抵达 seam。** `LlmModelReasoningInfo.defaultEffort` 本来就意味着「调用方没选档时要物化的档位」；现在由家族表供给，于是调用方什么都不选时拿到的是厂商自家平台使用的档（qwen3.8-max 的 `xhigh`、glm-5.3 与 Kimi K3 的 `max`、GPT-5 与 Claude Opus 5.5 的 `medium`、DeepSeek V4 与混元的 `high`），而不是无从查证的端点默认值。

**模型自己的 `maxTokens` 重新只是能力。** 两条 OpenAI 兼容线不再发送调用方没要过的上限；必须发这个字段的 Messages 协议按「调用方自己的值 → `extraBody.max_tokens` → `defaults.maxTokens` → 模型家族上限 → 未匹配家族的 64K」取值。这两处行为变化被写进升级指南，而不是静默吸收。

**能力编辑器把思考收进一组，并如实提出回传问题。** 编辑器里的思考控件现在同属「思考格式」一块，每行一个问题；其余声明合并为一行，而不是四个各含一个复选框的 fieldset。回传是三态答案——交由模型家族决定、回传、不回传——因为「清除」既不等于开也不等于关。

## Alternatives considered

**运行时从已安装的官方目录生成这张表。** 拒绝：裸档案就会依赖另一个包的数据，而目录里某个模型的条目属于**托管**服务商——正是第三条规则排除的出处。这张表由人读过一次，此后带着出处被引用。

**把默认值放进档案 schema，让每个部署各自声明。** 拒绝作为主要机制：那正是本次要消除的誊写工作，十一家的默认值会被每个部署重述一遍。档案保留最终话语权，这才是真正需要可配置的部分。

**把回传做成普通布尔值，并以 `false` 为默认。** 拒绝：对那些缺失即被拒绝的家族，它只能说谎，而按名拒绝是唯一诚实的表达位置。

**每次请求都发送家族默认档，包括调用方已选档的请求。** 拒绝：调用方自己的档位是更具体的指令，厂商默认档存在的意义只是填补沉默。

**为这张表单独用一种口语化格式（YAML 或 JSON 数据文件）。** 暂拒：lite 包发布的是打包好的 `lib/index.js`，没有资源管线，单独的数据文件需要额外的打包与运行时路径处理，而阅读体验并无改善；这个模块是一张扁平的表，每条带一行出处，并且有类型检查。

**保留只有官方目录作依据的家族。** 部分拒绝：ant-ling（`Ring-*`）家族因缺少自家平台文档被删除，而 LongCat 在读到其官方 API 文档后被恢复。保留下来的目录来源条目，都在出处行里如实标注。

## Consequences

只写 `models: [{ id: … }]` 的路由现在通常就够了：图片输入、思考格式、带厂商默认档的档位阶梯与回传行为都来自表；表里没有的模型行为与之前完全一致。

随之而来三处外部可见变化：模型自己的 `maxTokens` 不再在两条 OpenAI 线上变成请求上限；Messages 协议按「配置默认 → 家族上限 → 64K」取值；在强制回传的家族上关闭回传会被按名拒绝。三者都写进了升级指南。

这张表是数据而不是逻辑：新增一个模型家族就是加一条带出处的规则；测试文件钉住了每个代表型号归属的家族，因此插错顺序的规则会失败，而不是静默遮蔽另一条。

延后：逐思考档位的默认参数表（`samplingParamsByThinkingLevel` 类），设置页里编辑表内数值的入口，以及那些公布了档位集合却未公布默认档的家族的默认档。

## Testing

`tests/model-defaults.spec.ts` 钉住表本身——46 个代表型号解析到各自家族、大小写不敏感匹配、匹配与未匹配型号的 Anthropic 上限，以及四条不变式（每条规则都有出处、可匹配、不含采样字段、默认档属于该家族公布的档位集合）。`tests/model-defaults-wiring.spec.ts` 证明解析链与线上行为：裸档案被补齐、档案逐字段覆盖、强制回传拒绝关闭、路由未枚举的 id 拿到同样的事实、调用方未选档时写入家族默认档、调用方没要上限的 chat 请求不带 `max_tokens`、以及 Messages 上限链含 64K 兜底。既有的适配器、线路与客户端用例在其夹具编码了旧上限行为之处已更新，`packages/client/ui-settings-models/tests/owc-profiles.client.spec.tsx` 覆盖新的编辑器分组与两个显式回传答案。

本地已验证：适配器与设置客户端共 713 个测试、host 与 client 两个 TypeScript 工程类型检查、`oxlint` 零告警、`test:docs` 21/21 门禁、以及新声明对应的 `verify-config-catalog` 为最新。
