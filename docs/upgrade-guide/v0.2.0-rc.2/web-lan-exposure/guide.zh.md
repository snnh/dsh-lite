# Web profile 默认可从局域网访问

[English](guide.md) | 中文

## 变更

在此版本之前，`dsh web` 绑定 `127.0.0.1`，除运行它的机器之外无法访问 harness。现在它默认绑定**机器的局域网地址**——第一个自带网络的接口——因此同网络上的手机、平板或另一台电脑无需任何配置即可打开 Web UI。

可达绑定需要认证。每个非回环地址都要求 `$DSH_HOME/access-token`（写入权限 `0600`）处的持久访问令牌；当 home 中没有令牌时，首次启动会创建一个，`DSH_ACCESS_TOKEN` 可覆盖它。无法写入的 Harness home 不会退化为未认证绑定——本行会拒绝它，启动会带着原因失败。

有两件事刻意未变：命令行仍然拒绝 `--host 0.0.0.0`，绑定仍然由配置而非开关决定。变化的是随附 Web 组合所声明的姿态。

容器网桥、虚拟网络以及除所绑定接口之外的接口保持仅回环姿态：服务器绑定的是**一个**地址，而不是 `0.0.0.0`。选择该地址时，容器网桥（`docker0`、`br-<id>`）、veth 对、虚拟机交换机与隧道排在最后，因此容器宿主会绑定物理接口，即便 Docker 先报出自己的网桥；它们是**降权而非剔除**，仅有 VPN 接口地址的机器就绑定那个地址。

## 迁移

1. **保持仅回环姿态**，覆盖该行：

   ```yaml
   - id: lan-access
     name: '@deepseek-ai/dsh-host-lan-access'
     config:
       host: 127.0.0.1
   ```

   放进 profile 的 `cordis.patch.yml`，或用 `--patch` 传入。删除该行效果相同：Web bundle 把 `lanAccess` 声明为注入依赖，因此没有该行的树会绑定回环默认值。

2. **改为绑定所有接口**——适用于可达地址会变的机器或容器——设置 `host: 0.0.0.0`。安全边界仍是令牌；地址只决定哪些网络可以尝试认证。

3. **轮换令牌**：删除 `$DSH_HOME/access-token`（或修改 `DSH_ACCESS_TOKEN`）并重启。此前打印过的所有 URL 随即失效——这正是目的。

4. **如果选中的地址不是你要的那个**——机器有两个局域网，或它的物理接口并非手机能够到达的那个——把 `host` 设为你要的地址。默认选的只是**一个**网络，未必是你的那个。

5. **确认**：打印行会给出绑定的地址——`dsh web: http://192.168.1.5:3080/?token=…`——并且 `ss -ltn` 显示监听器落在该地址上，而不是 `127.0.0.1`。

### 安全边界

服务器不提供 TLS、不设置 `Secure` 属性、也不发送 HSTS 头。令牌随打印 URL 出现一次，随后在明文 HTTP 上变为 `HttpOnly` cookie，因此任何能看到网络路径的人都能读到它。请把局域网视为可信，或用终止 TLS 的反向代理、或限制谁能连接的虚拟组网挡在前面。本版本不提供按对端白名单、按用户身份或第二因素。
