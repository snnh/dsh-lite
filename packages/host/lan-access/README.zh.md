# @deepseek-ai/dsh-host-lan-access

[English](README.md) | 中文

## 概述

`@deepseek-ai/dsh-host-lan-access` 决定 Web 服务器绑定的地址。只要没有东西声明 host，它就发布本机持有的所有 IPv4 接口：首次启动会把 `host: 0.0.0.0` 写入该 profile 自己的 patch，因此之后每次启动绑定的都是这行持久化配置，而不是发行版的默认值。可达地址对任何能路由到它的人都是可达的，因此本行会拒绝它无法认证的绑定：每个非回环 host 都要求持久访问令牌，且本行会在启动日志中警告一次。把 `host` 设为 `127.0.0.1` 即让整棵树回到仅回环。

<a id="use-this-package"></a>
## 使用本包

### 选择绑定地址

本行挂载时不带 `host`，含义是"本机持有的所有 IPv4 接口"。随附的 Web 组合把它挂在 profile 之内，因此首次在没有声明 host 的激活中，它会把 `host: 0.0.0.0` 写入该 profile 的 `cordis.patch.yml`（权限 `0600`）。之后每次启动都把该值读回为组合后的行配置——profile patch 高于所有 bundle 默认值——因此该姿态比设置它的那个版本更长寿。删掉这个键，下次启动会重新写入随附姿态。

操作者声明的 host 按原样绑定，且不持久化任何内容。调用的 `--host` 排在第一位，其次是本行自己的 `host` 配置，因此 `--host 127.0.0.1` 只收窄单次运行，profile 里的 `host: 127.0.0.1` 则收窄每一次运行。两者在绑定之前都经过本行唯一的语法权威 `classifyBindHost`：回环拼写、`0.0.0.0` 通配地址或 IPv4 字面量按声明原样绑定，其余形式则直接让启动失败并把语法回述给操作者，而不是回退到随附姿态。

<a id="saving-an-address-from-the-settings-page"></a>
### 从设置页保存地址

「通用」设置页的监听地址行写入的就是同一个键：profile 自身 patch 中组合 `lan-access` 行的 `config.host`，并与该行 patch 配置里已有的其他键合并。一行存储、一个含义——从该页面保存的地址与手工编辑的地址对下次启动毫无区别，而且该页面读回的是持久化的那一行，不保留自己的副本。

这次保存刻意保持惰性。它写入文件后就结束：运行中的服务器保留它已绑定的地址，不创建访问令牌，不改写打印出的 URL，Loader 也不 reconcile。操作者需要重启才能生效，因此页面在生效之前会把已保存的地址与当前生效的地址并排显示。只有当地址是本行能绑定的形式时才接受写入，判定用的是与绑定同一个语法（`classifyBindHost`）：回环拼写（`127.0.0.1`、`localhost`、`::1`、`[::1]`）、`0.0.0.0` 通配地址，或一个 IPv4 字面量。输入的主机名，或 `::` 这类非回环 IPv6 字面量，会在落到文件之前被拒绝，而不是被持久化成一个无法启动的姿态；这个拒绝与手工编辑在下次启动会得到的是同一个，只是提前到还能改正的时候。这里保存的非回环地址同样只是一个请求：它所需的持久访问令牌由真正绑定它的那次启动创建，而不是由这次保存创建。

对声明了 `--host` 的那次运行，`--host` 依然高于已保存的那一行。页面会把这种情形报告为被钉定的姿态：地址已经写入，去掉该参数后才会生效。

没有可写入的 profile 时——直接挂载本行的嵌入方——回退是 `detectLanAddress()`：第一个自带网络的接口。容器网桥（`docker0`、`br-<id>`）、veth 对、虚拟机交换机（`virbr*`、`vmnet*`、`vboxnet*`）、隧道与覆盖网（`tun*`、`tap*`、`utun*`、`wg*`、`zt*`、`tailscale*`），以及平台自己的垫片——macOS 的 `bridge*`（它自带的虚拟机网桥）、`awdl*` 与 `llw*`（AirDrop 与 WiFi 伴随接口，对端根本路由不到），Windows/Hyper-V 的 `vEthernet (<switch>)`——排在最后：它们是手机够不到、操作者也没打算用的地址，而容器宿主常常把它们报在物理接口**之前**。它们只是排序靠后，不会被剔除——仅有 VPN 接口地址的机器仍然绑定它——而完全没有这类地址的机器绑定回环。这张表没有任何豁免：`br-` 名字一律降权，无论出自谁手；如果操作者的局域网确实落在这样命名的网桥上，应显式声明 `host`，而不是指望该名字被识别。

候选列表同样会把同一个接口自身的地址聚在一起。共享同一 MAC 的条目构成一段连续区间，区间内的接口名有序，因此本选择读到的接口来自平台本身，它们的先后顺序也是平台报告的顺序，而不是 `node:os` 恰好枚举条目的顺序。

本行发布的每个 host 都是 IPv4。`0.0.0.0` 是 IPv4 通配地址——所有接口，含容器网桥——而 `detectLanAddress()` 只读 IPv4 地址，因此需要 IPv6 暴露的宿主得用本行不提供的另一种面孔。回环是唯一走得更远的拼写：`::1` 与 `[::1]` 会被接受，因为它们和 `127.0.0.1` 一样只指向本机，绑定的是 IPv6 回环而非网络地址。

用 overlay 覆盖该选择：

```yaml
- id: lan-access
  name: '@deepseek-ai/dsh-host-lan-access'
  config:
    host: 127.0.0.1
```

| `host` | 姿态 |
|---|---|
| 省略 | 所有 IPv4 接口；profile 内首次启动会把 `0.0.0.0` 持久化进该 profile 的 `cordis.patch.yml` |
| `127.0.0.1` | 仅回环——harness 从网络不可达 |
| `0.0.0.0` | 所有 IPv4 接口，含容器网桥；不监听 IPv6 |
| `192.168.1.5` | 一个显式地址，必须是本机地址 |
| `localhost`、`::1`、`[::1]` | 同一个仅回环姿态，只是写成名字或 IPv6 回环字面量 |

该语法之外的一切——除 `localhost` 以外的主机名、`::` 这类非回环 IPv6 字面量、空值或带首尾空白的值——都会在启动时被拒绝，并把可接受的形式回述出来。

打印行会给出服务器应答的地址，先是回环，旁边是采样到的局域网地址：

```
dsh web: http://127.0.0.1:3080/?token=… (LAN: http://192.168.1.5:3080/?token=…)
```

可达绑定还会在启动日志里写入一条警告，说明绑定了什么、令牌是唯一认证者，以及如何收窄姿态。

### 回到回环

把 `host` 设为 `127.0.0.1`——写在 profile 的 `cordis.patch.yml` 里、「通用」设置页的监听地址行里，或用 `--host 127.0.0.1` 只对单次运行生效。此前启动持久化的键就是同一个键，因此编辑或删除它就是全部迁移工作；没有别处记录该姿态。删掉本行并不是回到回环的办法，因为随附的 `webserver` 行读取 `ctx.lanAccess.host`，而没有本行时 bundle 默认值会发布所有接口。

<a id="understand-the-implementation"></a>
## 理解实现

### 为什么默认发布所有接口

回环默认保护的是"没人要求暴露"的机器；而运行本 harness 的机器通常已经选择了可达，操作者的第一个问题是**如何用手里那台设备打开界面**。发布所有 IPv4 接口回答了这个问题，无论那台设备处于哪个网络：本机接入的每个网络——第二个局域网、虚拟交换机、容器网桥——都无需再配置一步即可访问，而只想发布其中之一的操作者改为声明那个地址。

持久化该姿态正是让这个默认值保持诚实的原因。没有点名 host 的操作者选的就是随附姿态，因此后续版本改动自身默认值时，绝不能悄悄移动一台已经启动过一次的机器：姿态由 profile 声明，而删掉那个键正是明确要求采用当前版本随附值的做法。没有 profile 的组合则保持较窄的回退，因为那里无处记录选择，而想要暴露的嵌入方可以自行声明。

### 拒绝覆盖了什么

回环绑定只需要连接半区已经施加的进程内认证。其它所有绑定——无论操作者声明还是随附姿态——都先要求持久令牌：Harness home 不可写、或配置值低于长度下限，都会让本行拒绝激活，于是不会有 Web 服务器绑定一个它无法认证的网络地址。可达绑定随后通过 `ctx.logger.warn` 与 `console.warn` 写入它的启动警告；console 那一份是必需的，因为默认 Web exporter 会过滤 `warn` 记录，而操作者可见的警告必须抵达终端。警告会点名所绑定的地址、作为唯一认证者的令牌、要编辑的 patch 文件，以及能收窄单次运行的 flag——绝不包含令牌本身；它是警告而非询问：暴露是操作者声明的姿态，这里不会阻塞启动。

## 延伸阅读

- `@deepseek-ai/dsh-client-connection` 用该令牌换取签名的浏览器 cookie，并拥有 Host/Origin 围栏。
- `@deepseek-ai/dsh-web-app` 读取 `ctx.lanAccess.host` 作为绑定，把可达地址采样进信任面、打印它们，并把它用作应用 URL 的 loopback 地址。

<a id="model-experience"></a>
## 模型体验

无，因为本行只决定 Web 服务器绑定的地址，并拒绝它无法认证的可达绑定；它不注册任何提示词、工具 schema 或会话事件。

#### KV Cache 影响

无；绑定姿态从不进入模型请求，可复用的提供方前缀因此不受影响。

<a id="known-limitations-and-deferred-work"></a>
## 已知限制与后续工作

- **没有 TLS、没有 `Secure` cookie、没有 HSTS。** 令牌随打印 URL 出现一次，随后在明文 HTTP 上变为 `HttpOnly` cookie。任何能看到网络路径的人都能读到它；超出可信网络的范围应使用反向代理或虚拟组网。
- **发布的姿态仅限 IPv4。** `0.0.0.0` 是 IPv4 通配地址，因此双栈机器只能经其 IPv4 地址访问，而不是 IPv6 地址；`detectLanAddress()` 也从不返回 IPv6 地址。语法接受 `::1` 与 `[::1]` 这两个 IPv6 回环拼写，它们只绑定本机；其余 IPv6 字面量一律不接受。
- **无法写入的 profile 会保留随附姿态却不记录它。** 本行会记录写入失败，并仍然绑定 `0.0.0.0`，因此操作者既看到暴露、也看到未能持久化的原因；而无法存放访问令牌的 Harness home 则会直接拒绝该绑定。
- **排序依据是接口名，不是路由。** 网桥与隧道被降权，但同级之间仍由操作系统枚举顺序决定。该选择只在没有 profile 声明 host 时运行，所以在意发布哪个网络的操作者应显式设置 `host`。
- **接口名是唯一的信号。** 这张表背后没有任何平台 I/O——不查路由，也不读 sysfs 或 WMI 的接口类型——因此表里没有的名字一律按真实接口处理：被操作者改过名的网桥、自带命名语法的虚拟化产品（比如 Parallels 的 `enp*`/`vnic*`），或交换机不叫 `virbr*`/`vmnet*`/`vEthernet*` 的平台，都会和物理接口同级排序，甚至赢得绑定；其边界在于：被降权的地址在别无选择时依然会被绑定，而 `host` 可以把这个选择直接说清楚。
- **信任围栏不是认证层。** 它拒绝跨站与 DNS rebinding 请求；认证由令牌承担。

<a id="dev-note"></a>
### 开发备注

#### 覆盖率

`packages/*/*/src` 带有逐文件 100% 的语句、分支与函数门禁。`resolveBindHost` 把探测到的地址作为参数接收，因此"配置值、探测值、两者皆无"三条分支都被钉住，而不依赖测试运行所在的机器；持久化路径则跑在真实的临时 profile 上，而不是桩件上。

#### 测试

`tests/lan-access.spec.ts` 按用例 stub `DSH_HOME`，在文件系统上观察令牌的创建、复用与拒绝。`tests/lan-access-posture.spec.ts` 在真实的 profile patch 上驱动持久化姿态：首次启用写入什么、写入的是 Loader 实际运行的那一行、已声明 host 时不会改动什么、哪种来源优先，以及启动警告说了什么。默认 host 的用例对照机器自身的探测结果断言，而非固定地址，因此它既适用于只有回环的 CI 容器，也适用于工作站。
