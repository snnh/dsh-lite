# @deepseek-ai/dsh-host-lan-access

[English](README.md) | 中文

## 摘要

`@deepseek-ai/dsh-host-lan-access` 决定 Web 服务器绑定的地址，并且**默认绑定机器的局域网地址**：harness 可以从手机、平板或同网络的另一台机器访问，而容器网桥与其它所有接口保持仅回环姿态。可达地址对任何能路由到它的人都是可达的，因此本行会拒绝它无法认证的绑定——每个非回环地址都要求持久访问令牌，本行在提供服务之前解析它（Harness home 没有时就创建一个）。把 `host` 设为 `127.0.0.1` 即让整棵树回到仅回环。

## 使用本包

### 选择绑定地址

本行挂载时不带 `host`，含义是"本机的局域网地址"。用 overlay 修改它：

```yaml
- id: lan-access
  name: '@deepseek-ai/dsh-host-lan-access'
  config:
    host: 127.0.0.1
```

| `host` | 姿态 |
|---|---|
| 省略 | 本机第一个非内部 IPv4 地址；没有则回环 |
| `127.0.0.1` | 仅回环——harness 从网络不可达 |
| `0.0.0.0` | 所有接口，含容器网桥 |
| `192.168.1.5` | 一个显式地址，必须是本机地址 |

打印行会给出服务器实际绑定的地址：

```
dsh web: http://192.168.1.5:3080/?token=…
```

### 回到回环

把 `host` 设为 `127.0.0.1`，或删除本行。Web bundle 把 `lanAccess` 声明为注入依赖，因此显式回环的树绑定回环，而本行自身的默认值是唯一会暴露机器的东西。

## 理解实现

### 为什么默认是局域网地址

回环默认保护的是"没人要求暴露"的机器；而运行本 harness 的机器通常已经选择了可达，操作者的第一个问题是**如何用手里那台设备打开界面**。绑定**一个**地址而不是所有接口，回答了这个问题，同时不额外监听容器网桥、虚拟网络以及机器碰巧持有的其它接口——暴露面因此与需求同样窄。

### 拒绝覆盖了什么

回环绑定只需要连接半区已经施加的进程内认证。其它所有绑定——无论探测得来还是配置指定——都先要求持久令牌：Harness home 不可写、或配置值低于长度下限，都会让本行拒绝激活，于是不会有 Web 服务器绑定一个它无法认证的网络地址。

## 延伸阅读

- `@deepseek-ai/dsh-client-connection` 用该令牌换取签名的浏览器 cookie，并拥有 Host/Origin 围栏。
- `@deepseek-ai/dsh-web-app` 把可达地址采样进信任面、打印它，并把它用作应用 URL。

## 已知限制与后续工作

- **没有 TLS、没有 `Secure` cookie、没有 HSTS。** 令牌随打印 URL 出现一次，随后在明文 HTTP 上变为 `HttpOnly` cookie。任何能看到网络路径的人都能读到它；超出可信局域网的范围应使用反向代理或虚拟组网。
- **本机第一个非内部 IPv4 地址胜出。** 拥有多个网络的机器（同时接 Wi-Fi 与有线的笔记本）会绑定其中之一；选择顺序取决于平台，所以在意绑哪一个的操作者应显式设置 `host`。
- **信任围栏不是认证层。** 它拒绝跨站与 DNS rebinding 请求；认证由令牌承担。

## 开发说明

### 覆盖率

`packages/*/*/src` 带有逐文件 100% 的语句、分支与函数门禁。`resolveBindHost` 把探测到的地址作为参数接收，因此"配置值、探测值、两者皆无"三条分支都被钉住，而不依赖测试运行所在的机器。

### 测试

`tests/lan-access.spec.ts` 按用例 stub `DSH_HOME`，在文件系统上观察令牌的创建、复用与拒绝。默认 host 的用例对照机器自身的探测结果断言，而非固定地址，因此它既适用于只有回环的 CI 容器，也适用于工作站。
